# Third-Party Attack Surface Monitor

Internal PwC web application for assessing the external attack surface of client third parties (vendors).

Analysts run everything from the browser at **http://localhost:8000**. Vendors never log in.

## Phase 1 status

Working today:

- Local login and roles (`analyst`, `engagement_lead`, `admin`)
- Client → engagement → vendor data model (SQLite, PostgreSQL-ready)
- Central scan **policy guard** with unit tests
- PwC-themed HTML UI (dashboard, vendor list, vendor detail tabs)
- Seeded demo engagement with three vendors and mocked findings

Later phases add Excel intake, live scans, modules, scoring, and reports.

## Requirements

- Python 3.12 (per-user install is fine)
- No Docker, WSL, or admin rights required
- Windows corporate laptop friendly (`start.bat` included)

## Quick start (Windows)

1. Double-click `start.bat`, **or**:

```bat
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
copy .env.example .env
python scripts\seed.py
python run.py
```

2. Open **http://127.0.0.1:8000**

## Quick start (macOS / Linux)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python scripts/seed.py
python run.py
```

The server binds to `127.0.0.1` only by default.

## Configuration

Copy `.env.example` to `.env`. Important keys:

- `SECRET_KEY` — session signing
- `FERNET_KEY` — file encryption (generated by seed if missing)
- `DATABASE_URL` — default SQLite `./data/tpm.db`
- Optional connector keys (Shodan, Censys, HIBP, GitHub) — unused until later phases

## External tools (later phases)

Place ProjectDiscovery Windows binaries in `tools/bin` (subfinder, dnsx, httpx, naabu, nuclei) and gowitness. A `setup_tools.py` helper will be added in Phase 3. Missing tools skip their modules instead of crashing.

## Moving to a server with PostgreSQL

1. Set `DATABASE_URL=postgresql+psycopg://user:pass@host:5432/tpm`
2. Install a PostgreSQL driver (`psycopg[binary]`)
3. Run Alembic migrations: `alembic upgrade head`
4. Set `HOST=0.0.0.0` only on a controlled network; keep auth and HTTPS in front

The SQLAlchemy models stay database-agnostic.
